🔬 Protocol Stack Explanations

TCP/IP & Three-Way Handshake

HTTP runs over TCP (Layer 4), which runs over IP (Layer 3). Before data transfer, TCP establishes a reliable connection via a 3-step handshake:

  1. SYN — Client initiates connection (Synchronize Sequence Number)
  2. SYN-ACK — Server acknowledges and sends its own SYN
  3. ACK — Client acknowledges; connection is established

Wireshark filter: tcp.port == 5000 and tcp.flags.syn == 1

HTTP Request-Response Cycle

Student browsers send HTTP GET/POST requests to the Flask server on TCP port 5000. Flask returns HTML responses. HTTP is stateless — sessions are maintained via server-side session cookies (HTTPONLY, SameSite=Lax).

Wireshark filter: http and tcp.port == 5000

DHCP — Dynamic Host Configuration Protocol

DHCP operates over UDP: Client (:68) → Server (:67). The 4-step DORA process automatically assigns IP, subnet mask, gateway, DNS, and lease time to connecting devices. This project simulates DORA without binding real UDP sockets or modifying network interfaces.

DNS — Domain Name System

DNS resolves hostnames to IP addresses over UDP port 53 (TCP for large responses). Our simulation resolves exam.local → 192.168.10.50 via a Python database lookup. No real DNS packets are generated by this simulation. For real exam.local browser access, a Windows hosts file entry or a local DNS server (e.g. dnsmasq) would be required.

IPv4 Subnetting

IPv4 addresses are 32-bit numbers divided by a subnet mask into Network ID and Host ID bits. The /24 mask (255.255.255.0) gives 254 usable hosts. Students can calculate any subnet using the built-in calculator.
